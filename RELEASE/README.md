# ALP Manager — حزمة الإصدار v1.0.0

نظام إدارة تقييد (Lockdown) لأجهزة Android عبر قنوات مدروسة القدرات، بواجهة عربية (RTL).

## الملفات
- `AndroidLockdownManager_Setup-v1.0.0.exe` — المثبّت (لكل مستخدم، بدون صلاحيات إدارة).
  التثبيت: شغّل الملف. الإزالة: الإعدادات > التطبيقات > ALP Manager > إلغاء التثبيت،
  أو `... --uninstall`.
- `AndroidLockdownManager-v1.0.0-windows-x64-portable.exe` — نسخة محمولة (شغّل مباشرة).
- `SHA256SUMS.txt` — بصمات التحقق للنسختين.
- `FINAL_RELEASE_VALIDATION_REPORT.html` — تقرير التحقق النهائي (بالعربية).
- `IMPLEMENTATION_CHANGELOG.md` — سجل التنفيذ.

## التحقق من البصمة
```powershell
Get-FileHash .\AndroidLockdownManager_Setup-v1.0.0.exe -Algorithm SHA256
```

## البيانات
تُحفظ البيانات في `%LOCALAPPDATA%\ALPManager\` (قاعدة البيانات، المفاتيح، التقارير)
ولا تتأثر بإعادة تثبيت النسخة المحمولة.

## الحالة
**READY FOR CONTROLLED PILOT — أُنجِز الجرى الأخضر الحقيقي**: على عينة **SM-J337P
فيزيائية** أكتمل على حافلة ADB الحقيقية: الاكتشاف، التسجيل
(`AVD-520041d74247b58b`)، الهوية الموسّعة (أمان/نواة/بوت/تشفير/مودم)، الفحص
المسبق، إصدار بيان الاسترداد، ثم **تطبيق `POL-PARTIAL` فعلي** بدليل REAL_DEVICE
(`EV-20260913-947AA082`) ولقطة التزام مكتوبة (UNKNOWN صادق حتى Device Owner).
خطوة DPC المتبقية تعلّق الرفع إلى PRODUCTION-READY بصدق — لا نجاح بلا دليل حقيقي.

## اكتشاف التوصيل تلقائيًا
صِل الهاتف عبر USB (مع تفعيل «تصحيح الأخطاء» وتأكيد الإذن على الجهاز) وسيتعرف
عليه التطبيق مباشرةً في صفحة «الأجهزة»: يعرض الجهاز المكتشف وحالته، ويعبّئ الرقم
التسلسلي تلقائيًا — اضغط «تسجيل الجهاز» لإكمال التسجيل. (تحديث تلقائي كل 4 ثوانٍ.)

## نموذج المصادقة (منذ إعادة البناء v1.0.0)
المنصة **لا تستخدم تسجيل دخول تفاعلي عند بدء التشغيل** — تفتح مباشرةً بوضع
«المشغّل المحلي». كل عملية حساسة (تطبيق سياسة / استرداد / تحديث نظام) تتطلب
**حيازة بيان استرداد خاص بالجهاز** (مشفّر عبر DPAPI في هذه الوحدة، يُعرض
معرّفه للعرض فقط، لا السرّ)، والعمليات الأشد (R1/R2) تتطلب تأكيدين باسْمَين
مختلفَين. التفاصيل في `AUTHENTICATION_AND_RECOVERY_DESIGN.html`.
