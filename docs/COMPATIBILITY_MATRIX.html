3) ملاحظات الإصدارات الحرجة (موثّقة)

API 24 (الحد الأدنى الفعلي لوكيلنا): عائلة add/clear/getUserRestriction في DPM — أي جهاز تحت 7.0 خارج نطاق الوكيل الحالي (يُصنَّف UNSUPPORTED لا «مدعوم جزئيًا»).
API 31 (انقسام الأذونات): ظهرت أذونات MANAGE_DEVICE_POLICY_* لكل قيد (مثال: ..._DEBUGGING_FEATURES) — مالك الجهاز يحتفظ بالوصول، لكن أي مسار بديل (تطبيق إدارة بصلاحية) يجب أن يطلب الإذن المطابق لكل قيد على 12+.
API 34+ (طبقة Global): قيد مالك الجهاز قد يستقر في طبقتي per-admin وGlobal معًا؛ clearUserRestriction(admin) يزيل طبقة المالك موثوقًا — البقايا العالمية تُرصد عبر المسبار (مُصمَّم في وكيلنا) لا تُدَّعى إزالتها.
OEM دائمًا: سلوك MTP/USB والرموز الهندسية يختلف (شوهد على J3: واجهة MTP تُعدّ رغم no_usb_file_transfer) — الحكم النهائي لأي جهاز = فحص القدرات الحي لا الجدول.

معايير الخروج: كل مستوى API أعلاه إما مُتحقق من التوثيق الرسمي أو موسوم NOT_VERIFIED — لا PASS بلا عتاد حي (§18).
