# دليل الاسترداد — RECOVERY_GUIDE

## متى يُستخدم
جهاز `NON_COMPLIANT` / فقدان سياسة / طلب إزالة / جهاز يحتاج `RECOVERY_REQUIRED`.

## الأوضاع (RecoveryEngine)
- **R1 استعادة**: بيان `CLEAR_POLICY` موقّع → إرسال → قراءة المسبار →
  `COMPLETE` (بلا قيود) / `PARTIAL` (بقايا مسمّاة) / `PLAN_ONLY` (بلا قراءة — صادق).
- **زر ROLLBACK داخل الوكيل**: نفس المسار بلا حاسوب (`UI-ROLLBACK-<ts>`).
- **R2 إعادة تجهيز**: 3 خطوات dpm (موافقة + `exec=True`).
- **R3 فلاش**: مرفوض دائمًا من التطبيق (`REFUSED_GOVERNANCE_LAB_ONLY`).
- **R4 تشخيص**: قراءة فقط.

## التفويض (§21)
`RECOVER` + شهادة الحيازة + موافقة مسمّاة → تنفيذ → `REC-/AUD-` → تحقق لاحق إلزامي (§41).

## أدوات الطوارئ (مستودع `scripts/`)
- `watch_and_restore.py`: مراقبة الظهور على ADB + إعادة تشغيل الخادم + تنفيذ `restore_default.py` تلقائيًا.
- `restore_default.py`: بيان CLEAR ← نفض الوكيل ← قراءة `state.json` ←
  `dpm remove-active-admin` ← تحقق `dumpsys` ← إلغاء التثبيت (أفضل جهد).

## المحظورات
- لا استرداد بلا هوية جهاز + تدقيق + تحقق.
- لا إعادة ضبط/فلاش إلا بتأكيدين مسمّيين، وFRP مسؤولية المالك (لا تجاوز مصرّح).
